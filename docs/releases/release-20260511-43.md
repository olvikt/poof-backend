# release-20260511-43

## Summary

Release `release-20260511-43` packages critical backend hardening after `bash scripts/deploy.sh release-20260510-42` with focus on order lifecycle safety, subscription/payment idempotency, API boundary tightening, courier contract normalization, and expanded critical release gates.

Primary operational outcome: safer retries, stricter invariants, and reduced risk of duplicate or economically invalid state transitions in checkout/subscription/payment/courier flows.

## Breaking / behavioral changes

1. Canonical courier accept endpoint changed:
   - **Canonical**: `POST /api/orders/offers/{offer}/accept`
   - Legacy endpoint `/api/orders/{id}/accept` still exists for transition compatibility.

2. Courier available-orders payload contract changed:
   - `/api/orders/available` no longer returns `order_id` as canonical client contract field.
   - Clients should rely on offer-centric contract fields (`offer` identity / linked public identifiers).

3. Client-facing order addressing tightened:
   - Public URLs and redirects now prefer `orders.public_id` to reduce IDOR risk.

4. Payment/subscription callbacks are now stricter:
   - Duplicate provider/subscription attempts should be deduplicated or rejected earlier.

## Migration risks and mandatory preflight

1. **`orders.public_id NOT NULL` preflight**
   - Verify no null/empty `public_id` rows remain before NOT NULL enforcement.
   - Confirm backfill coverage for historic rows and retry strategy for any outliers.

2. **Drop legacy unique `orders.subscription_id`**
   - Ensure app code no longer depends on old uniqueness assumption.
   - Validate replacement uniqueness/idempotency logic is active before migration.

3. **`subscription_run_slot` backfill/preflight**
   - Validate slot values are present and consistent for rows participating in subscription execution.
   - Ensure duplicate-slot detection/preflight query is clean before deploy.

4. **WayForPay provider transaction unique index**
   - Detect and resolve historical duplicates before unique index creation/enforcement.
   - Confirm callback path handles conflict/idempotency gracefully after index goes live.

## Post-deploy smoke check

1. Health/runtime baseline:
   - App health endpoint responds OK.
   - Queue worker processes subscription/payment callbacks without error spikes.

2. Order lifecycle:
   - Create order -> pay -> dispatch -> accept -> completion path executes without invalid FSM jumps.

3. Courier API contract:
   - `POST /api/orders/offers/{offer}/accept` works for valid active offer.
   - Legacy `POST /api/orders/{id}/accept` remains functional for compatibility period.
   - `/api/orders/available` response validated against new resource contract (no canonical `order_id`).

4. Payments/subscriptions:
   - Replayed callback/provider transaction does not create duplicate paid order/subscription execution.
   - WayForPay amount/currency validation rejects mismatched payloads.

5. Admin boundary:
   - Admin endpoints are inaccessible for non-admin tokens and accessible for admin tokens.
